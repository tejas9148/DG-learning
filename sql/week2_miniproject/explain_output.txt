OBSERVATION

The composite index was created on:

fact_orders(customer_key, date_key)

PostgreSQL still used a Sequential Scan after
creating the index.

This is because fact_orders contains only 21 rows.
For a very small table, a Sequential Scan can be
faster than using an index.

Therefore, the index benefit cannot be reliably
measured with only 21 rows.

A larger table would better demonstrate the
benefit of the index.



 INDEX SELECTION 

1. The query filters using customer_key and date_key.
2. Therefore, a composite index was created on both columns.
3. customer_key was placed first because it uses equality (=).
4. date_key was placed second because it uses a date range.
5. This index can reduce the number of rows PostgreSQL examines.
6. It is more useful when the fact table contains many rows.
7. EXPLAIN ANALYZE was used before and after creating the index.
8. PostgreSQL did not use the index because the table is very small.
9. The index is expected to be more useful as the table grows.
10. The query plan and execution time were compared to evaluate performance.
